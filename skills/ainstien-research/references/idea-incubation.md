# Idea Incubation

Use this guide when the user brings a raw idea or question, or when sources, discussions, confusions, patterns, or experiments spark possible research ideas.

## Purpose

Ideas should be captured before they are judged too harshly. Most early ideas are incomplete, but they preserve where the researcher's taste is developing.

The idea bank is not a claim sheet. It is a holding area for hunches, tensions, weird observations, possible experiments, and open questions that may later become claims.

## Raw Idea Intake

When the user brings an idea or question:

1. Record the user's wording verbatim or as close to verbatim as possible.
2. If the meaning is ambiguous, ask one focused question before interpreting it.
3. Search for field terminology, closest prior work, seminal and recent papers, contrary findings, standard methods, datasets, and benchmarks.
4. Build a short prior-art map: established knowledge, live disagreements, closest overlaps, novelty threats, and open space.
5. Return to the user with the search findings and refine the idea collaboratively.

Do not wait for the user to explicitly say "search" when research is needed to understand or evaluate the idea. Skip search only when the user asks not to browse or the current task is strictly about wording. If search is unavailable, disclose that limitation and propose exact queries and venues.

## Capture Triggers

Add to the idea bank when:

- A paper leaves an unresolved gap.
- The user asks a question that could become a direction.
- Multiple papers share a limitation or assumption.
- A result contradicts the user's expectation.
- A method seems useful in a different setting.
- A failure mode appears repeatedly.
- The user says "maybe", "what if", "I wonder", or "this feels important".

## Idea Record

For each idea, capture:

- Original user wording
- Unconfirmed interpretation, if needed
- Source that sparked it
- Why it may be interesting
- What would make it surprising to experts
- What would make it fruitful
- What evidence would be needed
- Feasibility notes
- Current status: raw, promising, merged, rejected, promoted-to-claim, testing

## Promotion Gate

Promote an idea to `claim-sheet.md` only when it can be stated as a precise, falsifiable claim.

Before promotion, show the exact one-sentence claim and wait for the user to confirm that it matches their meaning. Research findings can challenge or refine the idea, but must not silently rewrite it.

Before promotion, ask:

- What exactly would be true if this idea works?
- Who would be surprised?
- What would change downstream?
- What would falsify it?
- What is the smallest useful experiment?

## Output

Update `idea-bank.md` with the original wording and research findings. Save interpretations as unconfirmed. Then recommend whether to read more, sharpen, test, merge, or reject.
